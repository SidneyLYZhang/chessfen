# Brand Brief — chessfen (v2)

> 修订原因：v1 母题「开放弧线 + 斜线」没有体现产品最核心的两个事实——**棋盘**与 **FEN / PGN 编码**。v2 将母题整体替换为「棋盘格 + 编码序列」，配色、版式与应用约束沿用 v1。

## 2. 编码语义（v2 核心）

| 编码 | 结构事实 | 可转化为视觉的事实 |
|---|---|---|
| FEN | `rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR`；`/` 分隔 8 个 rank，数字压缩连续空格 | 离散、等距、沿单一方向的**线性分段**；`/` 的斜向 |
| PGN | `1. e4 e5 2. Nf3 Nc6 3. Bb5 …`；按回合编号的着法流 | 同样离散、等距、有序的**序列节奏** |
| 共性 | 两者都把二维棋盘压缩成一维文本 | **面 → 线** 的转译 |

## 3. Industry form language

科技 / 软件行业默认采用几何抽象、单轴结构、非对称平衡与高抽象容忍度。棋盘以 **2×2 交替格**（左上 / 右下实心）表达，而非 8×8 全网格，避免在小尺寸下糊成噪点；编码以三段等距离散短划表达，不使用字符字面量。

## 4. Scenario constraints

| Scenario | Min size | Monochrome required | Notes |
|---|---:|---|---|
| Favicon / App 图标 | 16×16 px | 是 | 最严苛场景；面与线必须分离 |
| 浏览器标签 / 状态栏 | 24×24 px | 是 | 保持明确正负形对比 |
| 官网页眉 | 高度 32–48 px | 否 | 需要横向标志与字标组合 |
| GitHub / API 文档 | 高度 24–48 px | 是 | 提供透明底 PNG 与 SVG |
| PPT / 文档 | 高度 24 px | 否 | 提供透明底 PNG 与 SVG |

## 5. Color constraints

无强制既有品牌色或禁忌色。色彩从参考视觉提取，遵循 1 个主色 + 1 个深色结构色 + 最多 1 个点缀色；必须提供单色版与反白版。

## 7. Design floor

- **必须同时可读出「棋盘」与「线性编码序列」**，二者缺一不可。
- 棋盘 = 2×2 交替格（左上 / 右下实心）；编码 = 三段等距离散短划。
- 面与线分占棋盘的两条对角、互不重叠，保证 16 px 与单色下不糊成一团。
- 禁止棋子字形、字母、数字字面量；编码特性由「离散 / 等距 / 线性」的节奏表达。
- 以 16×16 px Favicon 为最严苛场景，同时通过 24 px 单色辨识测试。
- 必须存在单色版与反白版；**深色背景必须用反白版**（深棕编码线在深底会完全消失，只剩两个赭金方格）。
- 禁止把渐变、阴影、纹理或颜色差异作为识别要素。
- 安全区 8 单位；不复制 Lichess 的具体马首轮廓。

## 8. Assumptions and open questions

- 默认品牌署名使用小写 `chessfen`。
- 默认不另造中文品牌名。
- 默认优先服务开发者工具场景，而非大众棋牌娱乐品牌。
- 默认需要 Favicon、横向字标、SVG、透明 PNG、单色与反白版本。
- 若希望「棋盘」识别更强，可增加方形外框；但外框在 16 px 基本不可见且会加大小尺寸密度，当前版本选择不加。
